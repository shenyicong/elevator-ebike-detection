你大概见过这样的画面：狭小的电梯轿厢里，一辆电动车硬挤进来，车把蹭着轿壁，电池离人只有几十厘米。

这不是小事。电动车进电梯后起火，从冒烟到爆燃往往只有几秒，而轿厢是一个几乎密闭的铁皮盒子。

"禁止电动车进电梯"贴了很多年，靠的却是自觉和物业盯梢。人盯屏幕会累，会漏，会走神。那么问题来了：能不能让机器替人盯住这一眼？

01

起点：不是一个模型，而是一双"能看见"的眼睛

项目叫电梯内电动车智能检测系统。听起来像论文题目，其实要做的事很朴素——让摄像头看懂电梯里发生了什么：有没有电动车、自行车、婴儿车，有没有人，有没有轮椅。

技术选型落在 YOLO11n 上，理由有三：

够轻  n 是 nano，小到能塞进边缘设备，不用依赖云端
够快  一次前向框出画面里所有目标，天然适合实时场景
够准  新一代 YOLO11 在小目标、密集场景上更稳

但要真正落地，第一道坎是数据。

02

数据：1.4 万张图，和一场"语义对齐"的暗战

数据集 图像 标注框
electric-bicycle-entering-elevator 8,193 16,455
lift-ebike 5,799 5,881

合起来是 13,992 张图像、22,336 个标注框，统一成 5 类：电动车、自行车、婴儿车、行人、轮椅。第二个数据集还多一个 test 集，正好留作跨域验证的试金石。

真正棘手的问题藏在类别里：第二个数据集只有 motorcycle 一类，没有"电动车"这个概念。 是把它映射成统一的 Electric-bicycle，还是保留成独立第 6 类？映射错了会引入语义漂移，保留错了两类会互相混淆。

我的做法是把它当成一个可证伪的问题：固定模型、轮次、尺寸、种子，只改标签体系，跑 A/B 对照。因为"我觉得"不算数，"测出来"才算数。

"数据的脏活，往往不在清洗，而在两个数据集对同一个词的理解不一样。"

04

成绩单：89.5% 到底意味着什么

指标数值一句话
mAP50 89.5% 宽松标准下的综合准确率
mAP50-95 73.5% 严格标准下，框还不够贴边
精确率 P 93.4% 报出来的框里真目标的比例
召回率 R 82.3% 所有真目标里被找到的比例

mAP50 和 mAP50-95 差了 16 个点，说明框的位置大体正确，但离严丝合缝还有距离——这是后续可以用更精细标注、更大尺寸去补的空间。

更有意思的是 P（93.4%）高于 R（82.3%）：模型偏谨慎，报出来的基本都是真的，但仍有约 18% 的目标没找到。对电梯安全来说这是合理的起点——误报多了，人就会把它当闹钟关掉。想要更多召回，调低置信度阈值即可，这是个可按需调节的旋钮。

"一个模型的性格，藏在 P 和 R 的差值里。"
05

让指标变成手感：上传一张图就能测

数字再漂亮，也得能亲手试。我把三个模型（两个单集模型 + 合并模型）导出成 ONNX，做成了一个纯前端在线演示：打开网页，上传一张电梯照片，浏览器里直接跑推理，检测框画在图上。

关键在于——图片不上传服务器，全部在本地浏览器里算，用的是 ONNX Runtime Web + WASM，只要有浏览器就能用。合并模型（mAP50 89.5%）被设为默认推荐。

06

高潮：从 2fps 到 98fps，慢的到底是谁

真正刺激的部分，是在网页做完之后。我的电脑是 Intel i5-11320H（4 核 8 线程，带 Iris Xe 核显）。一上手就发现：网页里检测一张图，慢得让人着急。于是做了一轮完整的后端实测（640×640，单张耗时中位数）：

网页 WASM 单线程 （现状） 464 ms 1×
ONNX Runtime CPU （原生 8 线程） 34 ms 13×
OpenVINO CPU 58 ms 8×
OpenVINO 核显 Iris Xe 10.2 ms 45×

第一，慢的不是模型，是浏览器。 同一个模型原生跑只要 34ms，网页 WASM 单线程却要 464ms，慢了 13 倍。所谓"电脑慢"，其实是"网页这套运行方式慢"。

第二，OpenVINO 的 CPU 反而比 ONNX Runtime CPU 慢（58ms vs 34ms）。这颗 4 核 CPU 上 OpenVINO 的 CPU 插件并不占优；它的强项是核显——iGPU 只要 10ms，比原生 CPU 还快 3 倍多。

"找瓶颈这件事，靠猜永远猜不中，只能一个个测过去。"

不过有个绕不开的现实：OpenVINO 是本地原生运行时，塞不进 GitHub Pages 这种纯静态网页。要让在线页真正快起来，两条路——网页 WebGPU 后端（仍是纯前端、图片不上传，最接近 98fps），或本地推理服务（电脑跑 OpenVINO，网页把图传给本机的它）。这也是项目下一步的重点。

07

写在最后：把"能不能做"变成"已经跑起来"

从头到尾，这个项目走完了一条完整的链路：数据获取与融合 → 模型训练与评估 → ONNX 导出 → 网页部署 → 性能剖析。代码、脚本、演示页全部开源，数据集也按原许可证（CC BY 4.0）标注清楚。

我越来越觉得，AI 项目最难的从来不是模型本身，而是把它从一个 mAP 数字，变成一个别人能点开、能上传照片、能亲眼看到结果的网页——再较真一点，去追问那 464ms 到底花在哪了。

技术的意义，是把"能不能做"
一步步变成"已经跑起来了"。
